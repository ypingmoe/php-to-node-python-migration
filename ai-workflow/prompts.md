# Prompt templates

Replace bracketed slots. Attach the real OpenAPI file or ADR when you run these. Reject output that adds attack procedures.

## 1. Migration checklist from OpenAPI

```text
You are a backend migration lead. Draft a route-by-route migration checklist
from the attached OpenAPI document.

Context:
- Legacy runtime: PHP
- New runtime: [Fastify | FastAPI]
- Pattern: strangler at the reverse proxy (one path at a time)
- Contract: [path to openapi.yaml]
- Phase in scope: [Phase 1 | list of operationIds]

For each operation produce:
- operationId, method, path
- PHP behavior to confirm (auth, status codes, error body)
- new-service tasks (handler, db, tests)
- proxy cutover step
- rollback step
- done when (observable acceptance check)

Rules:
- Defensive migration only. Do not describe exploits.
- Use the error codes already in the contract.
- Mark any assumption you introduce.
- Output Markdown checkboxes.
```

## 2. ADR draft

```text
You are writing an Architecture Decision Record.

Title: [title]
Status: Proposed
Decision I have already made: [one paragraph in my words]
Constraints: [team, runtime, deadline, security]

Write Context, Decision, and Consequences.
Keep the Decision faithful to what I made. You may clarify wording.
Consequences must include operational cost and rollback impact.
Do not add a different stack unless you put it under "Alternatives considered"
and leave it unchosen.
No exploit content.
```

## 3. Test plan

```text
You are writing a contract test plan for one API operation.

Operation: [method path]
Spec excerpt: [paste]
Runtimes that must pass: Fastify and FastAPI

List cases for:
- success
- validation failure
- auth missing
- auth present but forbidden
- not found
- one persistence side effect

For each case give the fixture name, expected status, expected error code
if any, and the assertion that protects parity between the two runtimes.
Do not include malicious payloads. Boundary tests for size and media type
must use the allowlist already in the spec.
```

## 4. Secure code review checklist

```text
Review this diff as a senior backend engineer doing a defensive review
of a PHP-to-[Node|Python] migration.

Diff: [paste or attach]
Contract: [operation]

Return a checklist with pass, fail, or n/a for:
- auth required where the contract says so
- owner checks on content and uploads
- problem+json error shape unchanged
- upload size and media allowlist enforced server-side
- storage key generated by the server
- secrets and connection strings only from the environment
- request id logged
- no new endpoint outside the contract
- no exploit, payload, or attack-simulation code

For each fail, quote the file and the smallest fix. Do not propose attacks.
```
